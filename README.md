# Рецепты долголетия — прототип

Локальный веб-интерфейс для демонстрации работы центра. FastAPI, Jinja2,
HTMX, Bootstrap 5, PostgreSQL и psycopg 3. Основой служат схемы в `docs/`.

## Запуск в PowerShell

Python 3.13+. Выполняйте команды из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env # только если своего .env ещё нет
```

Задайте пароль в `.env`, затем:

```powershell
docker compose up -d db
python -m scripts.setup_demo --seed
python -m scripts.setup_access --demo
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Если окружение уже настроено, достаточно
последних четырёх команд. Скрипт подготовки добавляет таблицы в отдельную схему
`prototype`, не меняя `public.items`. Демоданные вымышлены и загружаются только
в полностью пустую схему. Повторный запуск не перезаписывает пользовательские записи.
Без `--seed` создаются только таблицы. Не удаляйте Docker volume ради миграции.
Bootstrap и HTMX поставляются локально, доступ к CDN при показе не требуется.
В Windows используйте приведённую команду с `--reload`: этот режим Uvicorn
выбирает цикл событий, совместимый с асинхронным psycopg.

## Вход и роли

Откройте `/login`. `setup_access --demo` создаёт четыре демонстрационных входа:
`manager1`, `manager2`, `admin`, `director`. Случайные пароли выводятся в терминал
только при создании; повторный запуск сохраняет существующие пароли.
Пароли в файлы проекта не записываются; в БД хранятся хеши Argon2.

| Разделы | Менеджер | Администратор | Руководитель |
| --- | --- | --- | --- |
| Клиенты, визиты, договоры, продажи | Только свои | Все | Все |
| Номенклатура, остатки, движения, услуги и журнал услуг | Только свои | Все | Все |
| Оплаты | Назначенные ему | Все | Все |
| Программы | Просмотр | Просмотр | Просмотр и редактирование |
| Закупки, поставщики, сотрудники и показатели команды | Нет | Нет | Все |
| Учётные записи и роли | Нет | Нет | Все |

В карточках клиента и номенклатуры администратор и руководитель выбирают
«Ответственного менеджера». У менеджера новые клиенты и товары автоматически
относятся к его сотруднику; изменить ответственного он не может.
Визиты, договоры и продажи следуют за клиентом, складские записи и услуги —
за номенклатурой. Передача клиента или товара сразу меняет доступ к связанным
записям. Для продажи без клиента и оплаты ответственный задаётся отдельно:
документ-основание в исходной схеме хранится текстом.

Существующие записи без назначенного менеджера видят администратор и руководитель.
Демонстрационные клиенты и товары распределяются между двумя демоменеджерами;
скрипт не меняет уже назначенных ответственных.
Фильтры применяются на сервере к спискам, поиску, обзору, выбору связанных записей
и сохранению. Чужая карточка менеджеру возвращает 404; закрытый раздел и подстановка
чужой ссылки или ответственного возвращают 403. Старый API `/items` и `/docs`
доступны только руководителю.

Руководитель открывает «Учётные записи» и создаёт доступ для существующего сотрудника,
меняет роль, пароль или отключает вход. Изменение учётной записи отзывает её сессии;
последнего активного руководителя отключить нельзя. Сессия действует 8 часов,
выход отзывает её на сервере. Формы защищены CSRF-токенами.

Для первой учётной записи без демоданных:

```powershell
python -m scripts.setup_demo
python -m scripts.setup_access --username chief --employee-id 1 --role director
```

Сотрудник с указанным ID уже должен существовать в БД; пароль вводится скрыто в терминале.

## Что показать

1. Обзор: количество записей, ближайшие встречи и последние клиенты.
2. Клиенты: поиск, создание карточки и редактирование контактов.
3. Программы: описание, входящие услуги, одна стоимость и длительность.
4. Визиты: выбор клиента и сотрудника, дата, цель и статус.
5. Договоры: выбор клиента и программы, сроки и статус.
6. Продажи, платежи, склад, услуги и команда: ввод и редактирование записей.

Руководитель может создавать, искать и редактировать данные во всех 16 разделах.
Для остальных ролей набор разделов ограничен таблицей выше. Данные сохраняются
в PostgreSQL. Ошибки полей показываются в форме, введённые значения сохраняются.

## Границы прототипа

- Прототип предназначен для локального показа с вымышленными данными.
- Статусы, способы оплаты, длительность и документ-основание пока вводятся текстом.
- Входящие услуги программы — текстовое описание; позиции продаж и заказов — JSONB
  с табличным редактором в форме.
- Складские остатки, журналы и показатели сотрудников вводятся вручную.
  Продажа не списывает склад, платёж не меняет договор; суммы позиций не рассчитываются.
- Номера документов — поля схемы; внутренние `id` служат для адресации записей.
- Внешние ключи и дополнительные бизнес-связи не добавлены. Существование выбранных
  клиентов, сотрудников и других записей проверяется сервером при сохранении.
- Денежные поля форм используют Decimal и NUMERIC. Старый учебный `/items` сохранён.
- Время визитов хранится как местное время центра, без преобразований часового пояса.

## Проверка

```powershell
python -m pytest -p no:cacheprovider
python -m ruff check app tests scripts
```

Обычные тесты используют подменённый репозиторий. Отдельные проверки доступа
запускаются на настоящем PostgreSQL:

```powershell
$env:RUN_DB_TESTS = "1"
python -m pytest -p no:cacheprovider
Remove-Item Env:\RUN_DB_TESTS
```

Эти тесты создают временные учётные записи и данные, проверяют изоляцию двух
менеджеров, права ролей, попытки подстановки чужих ID, CSRF, выход, истечение
сессии и отключение входа. После выполнения удаляются только тестовые записи.
`/health` проверяет доступность приложения без входа.
